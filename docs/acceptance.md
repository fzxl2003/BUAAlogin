# 实机与能耗验收

原生编译与自动测试通过，不等于已经证明降低能耗。没有校园网、真实凭据、Windows/Linux 实机和测量数据时，以下验收必须标记为待测，不能填写推测结果。正式替换前执行本清单。

## 自动验证

- 原生测试覆盖固定加密向量（含中文／emoji）、JSONP、完整登录与在线快速路径、门户 IP 与本地 IP 不同的路由器 NAT、challenge IP、登录后在线确认、跳转限制、取消、退避、通知去抖、睡眠恢复、凭据缺失及 CLI SIGTERM。
- 每次发布执行 cargo test、fmt、clippy；Windows/macOS 原生构建；Docker test 阶段分别执行 Linux amd64/arm64 测试，运行层验证 --help 与缺凭据 --status 退出码。

## 实机功能

在 Windows 10/11 x64、macOS 12+ ARM、Linux amd64/arm64 分别记录系统、版本、构建 SHA、结果与日志。

1. 无 Python 环境解压启动；桌面版无需管理员权限，窗口、托盘、隐藏、显示、停止与退出正常。
2. 输入账号密码、检测／指定校园网接口、首次登录、已有认证状态、静默踢下线与自动重连。
3. 验证电脑通过路由器 NAT 接入校园网，登录参数使用门户识别的校园网 IP。另同时启用校园 Wi-Fi、USB 上联、VPN 与系统代理，确认认证请求仍从正确接口到网关，不泄露至其他上联。
4. 切换 IPv4、拔插网线、断开／重新连接 Wi-Fi；指定接口消失时等待该接口；通知风暴不产生重复认证。
5. 睡眠期间无认证请求，恢复仅合并检查一次；请求中停止／退出可取消传输，空闲中停止立即返回。
6. 记住凭据、重启读取、取消记住后删除；旧版凭据不被读取或删除。
7. Docker 必须有凭据，显式接口透传，多接口中一个失败不阻止其他接口在线；docker stop 正常退出，非 root 运行无需 NET_ADMIN/NET_RAW。
8. 对每张 Wi-Fi 网卡独立启用／关闭 BUAA-WiFi 自动连接，验证无 IP 时发现网卡、系统扫描结果触发连接、停止／睡眠暂停、权限不足提示和配置持久保存。
9. TLS 证书错误、HTTP/跨域跳转、异常 JSONP、错误密码及网关不可达，确认失败且日志无原始凭据／token。

## 能耗实验

固定同一设备、系统电源模式、屏幕状态、Wi-Fi、其他后台负载和检查间隔。依次对旧版及原生版各进行 **至少三次 30 分钟稳定在线测试**，交替运行顺序，每次只运行一个版本；另测断网等待、接口切换及重复失败。保留原始数据，采集器本身的开销须一致。

| 场景 | 版本 | 时长 | CPU 时间 | 常驻内存 | 唤醒次数 | 子进程创建 | 认证请求数 | 能耗/测量方法 |
|---|---|---|---|---|---|---|---|---|
| 稳定在线 1/2/3 | 旧版／原生 | 各 30 分钟 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |
| 无接口等待 | 旧版／原生 | 相同时长 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |
| 接口切换／失败 | 旧版／原生 | 相同操作 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |

macOS 用 Instruments 的 System Trace／Energy Log（视本机可用模板）记录 CPU、唤醒与进程创建，配合活动监视器及受控抓包统计请求；Windows 用 WPR/WPA 对比 CPU、进程生命周期、网络与可用电源指标；Linux 用 pidstat、perf／支持硬件上的功耗计数及容器统计。没有可归属到进程的功率指标时明确标记缺失，不将 RSS 下降当作实际节能百分比。

通过条件：稳定在线无子进程、重复接口扫描或 UI 周期刷新；每个健康接口每 300 秒最多一次状态请求（手动／网络事件触发单独统计）；无接口时无认证请求；睡眠、掉线、多接口和停止行为正确。CPU、唤醒与实际能耗相对基线降低；接近测量噪声则延长实验，不能宣称已证明节能。

通过后保存结果与构建 SHA，再手动运行 release workflow 的 promote_native。若出现认证或能耗回归，恢复此前发行版和对应镜像 SHA。
